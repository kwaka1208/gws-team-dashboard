# gws-team-dashboard

Google Workspace の組織で使う、**みんなで共有するタブと、各自の自分用のタブを分けた**ダッシュボードです。
Google Apps Script（GAS）の Web アプリとして動き、Google サイトに埋め込んで使えます。

[personal-dashboard](https://github.com/kwaka1208/personal-dashboard)（個人用・GitHub Pages＋Firebase 版）の画面とウィジェットを引き継ぎ、組織で使うための仕組みを足しました。

- **共有タブ**：全社向け・部署向け・プロジェクト向けなど、みんなで見るタブ。見られる人・編集できる人は、Google ドライブの共有設定で決まります
- **自分のタブ**：今までどおり自由に作れるタブ。本人しか見られません
- **お知らせウィジェット**：共有タブを見られる人へのお知らせ。未読の管理、重要なお知らせの帯、投稿・削除
- **書類ワークフロー**：テンプレートから Google ドキュメントの申請書を作り、提出 → 承認／差し戻し／拒否。やり取りはドキュメントのコメントに残ります
- ログインは不要（開いている Google アカウントで動きます）。Google カレンダー・Gmail も連携の操作なしで表示されます
- 費用はかかりません（Workspace のアカウントと Apps Script だけで動きます）

> **現在は試作版（v0.1）です。** 実際の Workspace で動かしながら直していく段階です。

## しくみ

```
Google サイト（埋め込み）
   └─ Apps Script の Web アプリ（開いている本人の権限で動く）
        ├─ 管理用スプレッドシート …… 共有タブの一覧
        ├─ 共有タブごとのスプレッドシート …… タブの中身 ＋ お知らせ
        └─ 本人の UserProperties …… 自分のタブ・お知らせの既読
```

**共有タブ 1 つに、スプレッドシートが 1 つあります。誰がそのタブを見られるか・編集できるかは、そのスプレッドシートの共有設定にそのまま従います。**
アプリの中に、権限やメンバーの設定はありません。

| スプレッドシートの共有 | 画面での扱い |
|---|---|
| 閲覧者 | タブとお知らせが見える。編集はできない（🔒） |
| 編集者 | タブの中身の変更、タブの追加、お知らせの投稿・削除ができる（✦） |
| アクセス権なし | タブ自体が表示されない |

共有の相手には、個人のアカウントも Google グループも指定できます。グループと共有しておけば、異動やメンバーの追加は、グループのメンバーを変えるだけで反映されます。グループの中に入れたグループ（入れ子）のメンバーにも、同じように見えます。

見せたくない人がいるタブは、別のスプレッドシート（別の共有タブ）に分けてください。閲覧者がスプレッドシートを直接開いても、読めるのは自分に共有されたファイルの中身だけです。

### 画面での見え方

- タブは「共有タブ ｜ 自分のタブ」の順に並びます。閲覧のみのタブには 🔒、編集できるタブには ✦ が付きます
- 閲覧のみのタブで何かを変えても保存されず、元に戻ります（「閲覧のみ」と表示されます）
- 共有タブを複製（⧉）すると、自分のタブとしてコピーでき、自由に変えられます
- 編集できる共有タブを開いて「編集」にすると、「＋ ◯◯にタブを追加」が出ます。同じ権限のまま、タブを増やせます（追加したタブも、同じスプレッドシートに入ります）

### 用語：「組織」シートと「種別」

管理用スプレッドシートでは、共有タブの一覧を「**組織**」シートに書きます。1 行が共有タブ 1 つ（スプレッドシート 1 つ）です。
「**種別**」は「全社」か「部署」で、並び順だけに使います（「全社」のタブが左、「部署」のタブがその右）。プロジェクトなど部署以外のタブは「部署」にしてください。

## 導入の手順

所要時間は 20〜30 分ほどです。導入する人（管理者）は、組織の Google Workspace アカウントで作業してください。

### 1. Apps Script のプロジェクトを作り、コードを入れる

コードの入れ方は、clasp（コマンドライン）を使う方法がおすすめです。

1. [script.google.com](https://script.google.com/) で **新しいプロジェクト** を作り、名前を付けます（例：チームダッシュボード）。
2. **プロジェクトの設定**（⚙）で、スクリプト ID をコピーします。
3. 手元のパソコンで次を実行します（Node.js が必要です）。

   ```sh
   npm install -g @google/clasp
   git clone https://github.com/kwaka1208/gws-team-dashboard
   cd gws-team-dashboard
   cp .clasp.json.example .clasp.json   # scriptId をコピーした ID に書き換える
   cp Makefile.example Makefile         # よく使う操作をまとめたもの（Git には入れません）
   make login                           # 組織のアカウントでログイン
   make push
   ```

   初めて clasp を使うときは、[Apps Script API の設定](https://script.google.com/home/usersettings) をオンにしてください。
   `make` だけを実行すると、使えるコマンドの一覧が出ます。

### 2. 画面の名前を決める（任意）

`src/config.js` の `title`（初期値「チームダッシュボード」）を変えると、ブラウザのタブや、作られるスプレッドシートの名前が変わります。変えたら `make push` し直します。

### 3. setup を実行する

1. [script.google.com](https://script.google.com/) からプロジェクトを開き、ファイル `setup.gs` を開きます。
2. 上の関数の選択で **setup** を選び、**実行** を押します。
3. 権限の確認が出たら、許可します。
4. **実行ログ**に、作られたスプレッドシートの URL が出ます。
   - 「チームダッシュボード（管理用）」…… 共有タブの一覧
   - 「チームダッシュボード：全社」…… 「全社」の共有タブとお知らせ

### 4. 共有を設定する

Google ドライブで、スプレッドシートを次のように共有します。

| スプレッドシート | 共有の相手と権限 |
|---|---|
| 管理用 | 組織内の全員：**閲覧者**（一覧を読むため。編集者は導入した管理者だけ） |
| 全社 | 組織内の全員：**閲覧者**／中身を整えたりお知らせを出したりする人：**編集者** |
| ほかの共有タブ | 見せたい Google グループ・アカウント：**閲覧者**／そのタブを管理する人：**編集者** |

管理用スプレッドシートには、共有タブの名前とスプレッドシートの ID しか入っていません。全員が閲覧できても、各タブの中身は見えません。

スプレッドシートは作った人のマイドライブにできます。共有ドライブに移しておくと、担当者が変わっても困りません。

### 5. 共有タブを足す

1. 管理用スプレッドシートの「組織」シートに、共有タブを 1 行ずつ書きます（**名前**＝タブの名前、**種別**＝部署、**並び順**。スプレッドシート ID は空のまま）。
   例：「営業部」「営業部・管理職」「プロジェクト A」
2. Apps Script のエディタで **syncUnits** を実行します。ID が空の行に、その共有タブのスプレッドシートが作られます。
3. 作られたスプレッドシートを、手順 4 のとおりに共有します。

共有タブをやめるときは、「組織」シートからその行を消します（スプレッドシートは残るので、不要なら別に削除してください）。

### 6. Web アプリとして公開する

1. エディタの **デプロイ → 新しいデプロイ** を開き、種類に **ウェブアプリ** を選びます。
2. 次のように設定して **デプロイ** を押します。
   - 次のユーザーとして実行：**ウェブアプリケーションにアクセスしているユーザー**
   - アクセスできるユーザー：**（組織名）内の全員**
3. 表示された URL（`https://script.google.com/a/macros/…/exec`）を開いて、動くか確かめます。

4. **デプロイ → デプロイを管理** に出るデプロイ ID を、`Makefile` の `DEPLOY_ID` に書きます。

コードを直したら、次のどちらかで公開中のアプリを更新します。どちらも同じデプロイ ID のまま新しいバージョンにするので、URL は変わりません。

```sh
make deploy d="お知らせの表示を修正"   # 説明を付けて更新
make release v=v0.2                   # テスト → src/config.js のバージョンを書き換え → push → 更新
```

作業中の確認は、`make push` してから、エディタの **デプロイ → デプロイをテスト** の URL（末尾が `/dev`）で行うと、デプロイし直さずに最新のコードを試せます。

### 7. Google サイトに埋め込む

1. Google サイトで、ページの **挿入 → 埋め込む → URL** に、手順 6 の URL を貼ります。
2. 埋め込んだ枠を、画面に合わせて大きめに広げます（枠の高さは自動では伸びません）。

全画面で使うなら、サイトに埋め込まず、Web アプリの URL をそのままブックマークするほうが快適です。

### 利用者が初めて開いたとき

一人ひとり、初回だけ権限の確認画面が出ます（Google カレンダー・Gmail の未読件数・スプレッドシート・ドライブ・メールの送信・Google グループの確認など）。
「許可」すると、以降は出ません。

## お知らせの使い方

- **投稿**：共有タブの編集者が、お知らせウィジェットの「＋ 投稿」から書きます。本文は Markdown が使えます。お知らせは、その共有タブを見られる人全員に表示されます
- **重要**：「重要」にすると、未読の人の画面の上に帯で出ます
- **掲載期間**：掲載開始日・掲載終了日を入れると、その期間だけ表示します（空なら期限なし）
- **既読**：本文を開くと既読になります。既読は人ごとに保存され、別の端末でも引き継がれます
- **シートから直接**：共有タブのスプレッドシートの「お知らせ」シートに 1 行足しても投稿できます（ID は空のままで構いません）。まとめて直したいときや、過去分の整理に使えます

お知らせウィジェットは、自分のタブにも置けます。ウィジェットの設定で、見られる共有タブすべてのお知らせを出すか、特定の共有タブのお知らせだけを出すかを選びます。

## 書類ワークフロー（申請・承認）

テンプレートから Google ドキュメントを作り、提出・承認するウィジェットです。
申請書そのものが Google ドキュメントなので、質問や修正の相談はドキュメントのコメントで行い、そのまま記録として残ります。

### 流れとステータス

```
[提出前] ──提出──▶ [提出後] ──承認──▶ [承認後]（ドキュメントはロック）
    ▲                │
    └──差し戻し／取り下げ─┤
                     └──拒否──▶ [拒否後]
```

| 操作 | できる人 |
|---|---|
| ＋ 新規作成（テンプレートをプルダウンで選ぶ） | 保存先フォルダの編集者 |
| 提出・取り下げ | 書類を作った人 |
| 承認・差し戻し・拒否 | その書類の承認者（承認者のうち 1 人が判断すれば進みます） |

- 作成者は、承認されるまでドキュメントを書き換えられます。承認されると、ドライブの「ロック」で書き換えられなくなります
- 提出・承認・差し戻し・拒否・取り下げのたびに、ドキュメントにコメントで経緯（誰が・いつ・理由）を書き込み、相手にメールで知らせます
- 差し戻し・拒否のときは、理由の入力が必須です
- 一覧には、ファイル名・ステータス・テンプレート・作成者・更新日が出ます。ステータスで絞り込めます。自分が承認者の書類は色が付き、「あなたの承認待ち n 件」と表示されます

### 設定のしかた

1. 書類を入れる **保存先フォルダ** を Google ドライブに作り、使う人全員を **編集者** にします（フォルダを見られる人は、中の書類をすべて見られます）。
2. テンプレートにする Google ドキュメントを作り、使う人が **閲覧** できるように共有します。
3. ダッシュボードの「編集」→「＋ ウィジェットを追加」で **書類ワークフロー** を選び、次を設定します。
   - **保存先のフォルダ**：手順 1 のフォルダの URL
   - **テンプレート**：名前・テンプレートの URL・承認者を、テンプレートの数だけ。承認者はメールアドレス（Google グループも可）で、カンマ区切りで 5 件まで。空にしたテンプレートは、提出するときに承認者を指定します
   - **作る書類の名前**：`{件名}` `{テンプレート}` `{作成者}` `{日付}` を組み合わせます（空なら `{件名}_{作成者}_{日付}`）

保存先フォルダの中には、最初に書類を作ったときに「提出前」「提出後」「承認後」「拒否後」のフォルダが自動でできます。ステータスは、書類がどのフォルダにあるかで決まります。ドライブで書類を別のフォルダに動かすと、ステータスも変わります。

ウィジェットを共有タブに置けば、そのタブを見られる人全員が使えます。テンプレートと承認者を変えられるのは、そのタブの編集者だけです。承認者の設定はサーバーが保存済みのウィジェット設定から読むので、申請者が画面上で書き換えることはできません。

### 注意

- 承認者に Google グループを指定した場合、判定できるのはグループの**直接のメンバー**だけです（グループの中に入れたグループのメンバーは、承認者として扱われません）
- このウィジェットを追加した版から、権限として「Google ドライブのファイルの作成・編集」「メールの送信（あなたの名前で）」「所属する Google グループの確認」が増えています。更新するときは次のようにしてください
  1. `make push-force`（`clasp push --force`）で、`appsscript.json` も送る。ふつうの `clasp push` は「Manifest file has been updated. Do you want to push and overwrite?」と聞いてきて、既定（Enter）だと権限の設定が送られません
  2. Apps Script のエディタで **authorize** を実行し、許可の画面で許可する（何も書き換えない、許可のためだけの関数です）
  3. ほかの人は、更新後に開いたときに許可の画面が出ます。「権限がまだ許可されていません」と出た人は、[Google アカウントのサードパーティ製アプリの設定](https://myaccount.google.com/connections) からこのアプリへのアクセスを削除し、開き直して許可します

## 知っておいてほしいこと

- **複数の Google アカウントでログインしているブラウザ**では、Apps Script の Web アプリが正しく動かないことがあります（Google 側の制限）。このアプリを使うアカウントだけでログインしたブラウザのプロファイルで開いてください
- **反映のタイミング**：ほかの人の変更は、3 分ごとと、画面に戻ってきたときに読み直して反映します（即時ではありません）。共有タブの中身は最大 2 分、どのタブを見られるか・編集できるかの判定は最大 10 分キャッシュします。共有設定を変えたときは、少し待ってから開き直してください
- **保存できる量**：自分のタブは 1 人あたり約 400KB まで（Apps Script の UserProperties の上限）。写真はファイルを取り込まず、URL で登録してください
- **天気の「現在地を使う」** は、埋め込みの枠の中では位置情報が使えず、動かないことがあります。地名で指定してください
- **D キー**（ライト／ダークの切り替え）などのキー操作は、サイトに埋め込んだときは枠の中を一度クリックしてから使えます
- 共有タブの編集が 2 人で重なったときは、項目ごとにまとめてから保存します（同じウィジェットを同時に変えた場合は、後から保存した人の内容になります）

## ファイルの構成

Apps Script に送るのは `src/` だけです（`.clasp.json` の `rootDir`）。

| ファイル | 役割 |
|---|---|
| `src/main.js` | Web アプリの入り口（`doGet`）。最初の表示に必要なデータを埋め込む |
| `src/api.js` | 画面から呼ぶ関数（`google.script.run`） |
| `src/service_*.js` | 個人のデータ・共有タブ・お知らせ・書類ワークフロー・カレンダー／Gmail の処理（コードの中では、共有タブのまとまりを unit と呼んでいます） |
| `src/setup.js` | 管理者がエディタから実行する `setup` / `syncUnits` |
| `src/config.js` | シート名・列名・上限などの定義 |
| `src/index.html` | 画面のもと。CSS・JS を `include_()` で読み込む |
| `src/js_storage.html` | サーバーとのやり取り。共有タブと自分のタブを分けて保存する |
| `src/js_app.html` | 画面とウィジェット（personal-dashboard の app.js が元） |
| `src/css_*.html` | 見た目（`css_org.html` が共有タブとお知らせ、`css_custom.html` が着せ替え用） |
| `dev/` | デプロイせずに画面を確かめるためのプレビュー（`make preview` → `dev/preview.html`） |
| `Makefile.example` | clasp のよく使う操作（`make help` で一覧）。`Makefile` にコピーして、`DEPLOY_ID` を書いて使う |
| `tests/` | テスト（`make test`）。サーバー側の処理と、画面の JS が Apps Script の書き出しで壊れないか |

### 見た目を変える

`src/css_custom.html` に CSS 変数を書いて上書きします（例：`--color-accent: #202f55;`）。
変数の一覧は `src/css_tokens.html` にあります。

### 自作のウィジェット（アドオン）

`src/js_addons.html` の中で `PD.addon_api.registerWidget({ … })` を呼ぶと、ウィジェットの種類を足せます。
書き方は personal-dashboard の [WIDGET.md](https://github.com/kwaka1208/personal-dashboard/blob/main/WIDGET.md) と同じです（`import` の代わりに `PD.addon_api` を使います）。
