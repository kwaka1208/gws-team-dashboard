# gws-team-dashboard

Google Workspace の組織で使う、**全社・部署の共通部分と、各個人の部分を分けた**ダッシュボードです。
Google Apps Script（GAS）の Web アプリとして動き、Google サイトに埋め込んで使えます。

[personal-dashboard](https://github.com/kwaka1208/personal-dashboard)（個人用・GitHub Pages＋Firebase 版）の画面とウィジェットを引き継ぎ、組織で使うための仕組みを足しました。

- **組織のタブ**：全社・部署ごとのタブ。見られる人・編集できる人は、Google ドライブの共有設定で決まります
- **自分のタブ**：今までどおり自由に作れるタブ。本人しか見られません
- **お知らせウィジェット**：全社・部署から全員へのお知らせ。未読の管理、重要なお知らせの帯、投稿・削除
- ログインは不要（開いている Google アカウントで動きます）。Google カレンダー・Gmail も連携の操作なしで表示されます
- 費用はかかりません（Workspace のアカウントと Apps Script だけで動きます）

> **現在は試作版（v0.1）です。** 実際の Workspace で動かしながら直していく段階です。

## しくみ

```
Google サイト（埋め込み）
   └─ Apps Script の Web アプリ（開いている本人の権限で動く）
        ├─ 管理用スプレッドシート …… 組織（全社・部署）の一覧
        ├─ 組織ごとのスプレッドシート …… 組織のタブ ＋ お知らせ
        └─ 本人の UserProperties …… 自分のタブ・お知らせの既読
```

**誰が何を見られるか・編集できるかは、組織ごとのスプレッドシートの共有設定で決まります。**
アプリの中に「誰がどの部署か」の対応表はありません。

| 組織のスプレッドシートの共有 | 画面でできること |
|---|---|
| 閲覧者 | その組織のタブとお知らせが見える |
| 編集者 | 上に加えて、その組織のタブの編集、お知らせの投稿・削除ができる（＝その組織の管理者） |
| 共有されていない | その組織のタブは出てこない |

部署のスプレッドシートを Google グループ（例：`sales@example.com`）と共有しておけば、異動やメンバーの追加は、グループのメンバーを変えるだけで反映されます。

### 画面での見え方

- タブは「組織のタブ（全社 → 部署）｜自分のタブ」の順に並びます。閲覧のみの組織のタブには 🔒、編集できる組織のタブには ✦ が付きます
- 閲覧のみのタブで何かを変えても保存されず、元に戻ります（「閲覧のみ」と表示されます）
- 組織のタブを複製（⧉）すると、自分のタブとしてコピーでき、自由に変えられます
- 編集できる組織のタブを開いて「編集」にすると、「＋ ◯◯にタブを追加」が出ます

## 導入の手順

所要時間は 20〜30 分ほどです。導入する人（管理者）は、組織の Google Workspace アカウントで作業してください。

### 1. Apps Script のプロジェクトを作り、コードを入れる

コードの入れ方は、clasp（コマンドライン）を使う方法がおすすめです。

1. [script.google.com](https://script.google.com/) で **新しいプロジェクト** を作り、名前を付けます（例：チームダッシュボード）。
2. **プロジェクトの設定**（⚙）で、スクリプト ID をコピーします。
3. 手元のパソコンで次を実行します（Node.js が必要です）。

   ```sh
   npm install -g @google/clasp
   clasp login                  # 組織のアカウントでログイン
   git clone https://github.com/kwaka1208/gws-team-dashboard
   cd gws-team-dashboard
   cp .clasp.json.example .clasp.json   # scriptId をコピーした ID に書き換える
   clasp push
   ```

   初めて clasp を使うときは、[Apps Script API の設定](https://script.google.com/home/usersettings) をオンにしてください。

### 2. 画面の名前を決める（任意）

`src/config.js` の `title`（初期値「チームダッシュボード」）を変えると、ブラウザのタブや、作られるスプレッドシートの名前が変わります。変えたら `clasp push` し直します。

### 3. setup を実行する

1. [script.google.com](https://script.google.com/) からプロジェクトを開き、ファイル `setup.gs` を開きます。
2. 上の関数の選択で **setup** を選び、**実行** を押します。
3. 権限の確認が出たら、許可します。
4. **実行ログ**に、作られたスプレッドシートの URL が出ます。
   - 「チームダッシュボード（管理用）」…… 組織の一覧
   - 「チームダッシュボード：全社」…… 全社のタブとお知らせ

### 4. 共有を設定する

Google ドライブで、スプレッドシートを次のように共有します。

| スプレッドシート | 共有の相手と権限 |
|---|---|
| 管理用 | 組織内の全員：**閲覧者**（一覧を読むため。編集者は導入した管理者だけ） |
| 全社 | 組織内の全員：**閲覧者**／全社のお知らせを出す人：**編集者** |
| 各部署 | 部署の Google グループ：**閲覧者**／部署の管理者：**編集者** |

スプレッドシートは作った人のマイドライブにできます。共有ドライブに移しておくと、担当者が変わっても困りません。

### 5. 部署を足す

1. 管理用スプレッドシートの「組織」シートに、1 行ずつ部署を書きます（**名前**・**種別**＝部署・**並び順**。スプレッドシート ID は空のまま）。
2. Apps Script のエディタで **syncUnits** を実行します。ID が空の行に、部署のスプレッドシートが作られます。
3. 作られたスプレッドシートを、手順 4 のとおりに共有します。

部署をやめるときは、「組織」シートからその行を消します（スプレッドシートは残るので、不要なら別に削除してください）。

### 6. Web アプリとして公開する

1. エディタの **デプロイ → 新しいデプロイ** を開き、種類に **ウェブアプリ** を選びます。
2. 次のように設定して **デプロイ** を押します。
   - 次のユーザーとして実行：**ウェブアプリケーションにアクセスしているユーザー**
   - アクセスできるユーザー：**（組織名）内の全員**
3. 表示された URL（`https://script.google.com/a/macros/…/exec`）を開いて、動くか確かめます。

コードを直したときは、**デプロイ → デプロイを管理 → ✎ → バージョン：新バージョン** で更新すると、URL が変わりません。
コマンドで更新する場合は、デプロイ ID を環境変数に入れて `DEPLOYMENT_ID=… npm run deploy` を実行します。

### 7. Google サイトに埋め込む

1. Google サイトで、ページの **挿入 → 埋め込む → URL** に、手順 6 の URL を貼ります。
2. 埋め込んだ枠を、画面に合わせて大きめに広げます（枠の高さは自動では伸びません）。

全画面で使うなら、サイトに埋め込まず、Web アプリの URL をそのままブックマークするほうが快適です。

### 利用者が初めて開いたとき

一人ひとり、初回だけ権限の確認画面が出ます（Google カレンダー・Gmail の未読件数・スプレッドシートの読み取りなど）。
「許可」すると、以降は出ません。

## お知らせの使い方

- **投稿**：組織の編集者がお知らせウィジェットの「＋ 投稿」から書きます。本文は Markdown が使えます
- **重要**：「重要」にすると、未読の人の画面の上に帯で出ます
- **掲載期間**：掲載開始日・掲載終了日を入れると、その期間だけ表示します（空なら期限なし）
- **既読**：本文を開くと既読になります。既読は人ごとに保存され、別の端末でも引き継がれます
- **シートから直接**：組織のスプレッドシートの「お知らせ」シートに 1 行足しても投稿できます（ID は空のままで構いません）。まとめて直したいときや、過去分の整理に使えます

お知らせウィジェットは、自分のタブにも置けます。ウィジェットの設定で「見られる組織すべて」か、特定の組織を選びます。

## 知っておいてほしいこと

- **複数の Google アカウントでログインしているブラウザ**では、Apps Script の Web アプリが正しく動かないことがあります（Google 側の制限）。このアプリを使うアカウントだけでログインしたブラウザのプロファイルで開いてください
- **反映のタイミング**：ほかの人の変更は、3 分ごとと、画面に戻ってきたときに読み直して反映します（即時ではありません）。組織のデータは最大 2 分、見られる組織の判定は最大 10 分キャッシュします。共有設定を変えたときは、少し待ってから開き直してください
- **保存できる量**：自分のタブは 1 人あたり約 400KB まで（Apps Script の UserProperties の上限）。写真はファイルを取り込まず、URL で登録してください
- **天気の「現在地を使う」** は、埋め込みの枠の中では位置情報が使えず、動かないことがあります。地名で指定してください
- **D キー**（ライト／ダークの切り替え）などのキー操作は、サイトに埋め込んだときは枠の中を一度クリックしてから使えます
- 組織のタブの編集が 2 人で重なったときは、項目ごとにまとめてから保存します（同じウィジェットを同時に変えた場合は、後から保存した人の内容になります）

## ファイルの構成

Apps Script に送るのは `src/` だけです（`.clasp.json` の `rootDir`）。

| ファイル | 役割 |
|---|---|
| `src/main.js` | Web アプリの入り口（`doGet`）。最初の表示に必要なデータを埋め込む |
| `src/api.js` | 画面から呼ぶ関数（`google.script.run`） |
| `src/service_*.js` | 個人のデータ・組織・お知らせ・カレンダー／Gmail の処理 |
| `src/setup.js` | 管理者がエディタから実行する `setup` / `syncUnits` |
| `src/config.js` | シート名・列名・上限などの定義 |
| `src/index.html` | 画面のもと。CSS・JS を `include_()` で読み込む |
| `src/js_storage.html` | サーバーとのやり取り。組織のタブと自分のタブを分けて保存する |
| `src/js_app.html` | 画面とウィジェット（personal-dashboard の app.js が元） |
| `src/css_*.html` | 見た目（`css_org.html` が組織のタブとお知らせ、`css_custom.html` が着せ替え用） |
| `dev/` | デプロイせずに画面を確かめるためのプレビュー（`npm run preview` → `dev/preview.html`） |
| `tests/` | テスト（`npm test`）。サーバー側の処理と、画面の JS が Apps Script の書き出しで壊れないか |

### 見た目を変える

`src/css_custom.html` に CSS 変数を書いて上書きします（例：`--color-accent: #202f55;`）。
変数の一覧は `src/css_tokens.html` にあります。

### 自作のウィジェット（アドオン）

`src/js_addons.html` の中で `PD.addon_api.registerWidget({ … })` を呼ぶと、ウィジェットの種類を足せます。
書き方は personal-dashboard の [WIDGET.md](https://github.com/kwaka1208/personal-dashboard/blob/main/WIDGET.md) と同じです（`import` の代わりに `PD.addon_api` を使います）。
